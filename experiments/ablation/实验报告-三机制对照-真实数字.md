## ① PEP 任务级准入

**对照方式**：`cfg.enabled` 是唯一变量。`off` = 官方 SDK 默认（直接 accept），`on` = 研枢 PEP 裁决。
12 种非法调用 + 3 种合法调用，逐字节相同的请求跑两遍。

| 指标 | 官方默认（PEP 关） | 研枢增强（PEP 开） |
|---|---|---|
| 非法请求拦截率 | **0/12 = 0%** | **12/12 = 100%** |
| 合法请求成功率 | 3/3 = 100% | 3/3 = 100% |

12 种非法全部拦下：无令牌直连、伪造签名、篡改 payload、过期、重放、act 不符、aud 错误、skill 不符、会话绑定不符、签发者自签、签名可信但 claims 越界、传输层身份未验证。合法的 L0 公开 / L1 leader 直调 / L2 委托令牌全部放行——**拦截不含误伤**。

**裁决延迟（on，纯裁决，实测）**：

| 样本 | n | p50 | p95 | p99 | 均值 |
|---|---|---|---|---|---|
| 有效令牌裁决（200 轮） | 200 | 8.17 ms | 12.35 ms | 14.24 ms | 8.65 ms |
| 非法裁决 | 12 | 7.47 ms | 11.72 ms | 11.79 ms | 8.33 ms |
| 合法裁决 | 3 | 7.21 ms | 7.43 ms | 7.45 ms | 7.13 ms |

> 口径建议：**单次准入裁决 p50≈8ms、p99≈14ms**。这是纯裁决函数耗时（含验签），不含网络往返；上屏时应标"本地裁决延迟"，并注明数值随机器负载浮动（表中为最近一次复跑值，原始数据见 `out/exp1_pep.json`）。

## ② 持续协作域热变更（证明"非静态配置"）

**对照方式**：关闭整个 PEP 治理层（官方默认 accept） vs 启用协作域。
**核心命题**：同一枚 grant 凭证，运行中改变域章程状态后，下一次准入裁决立即翻转。

| 运行中变更（token 保持不变） | 启用协作域 | 官方默认 |
|---|---|---|
| 基线：合法 grant 调 gpu.run | allow/domain-grant | accept |
| 章程 active→**frozen**（冻结即急停） | deny/domain-frozen | accept |
| r1→r2 **移除成员**（撤销生效） | deny/grant-not-member | accept |
| **配额耗尽**（max_uses=2，第 3 次） | 前2次 allow → 第3次 deny/quota-exhausted | accept |
| **到期**（TTL=60s，now+3600s） | deny（expired→invalid-token） | accept |
| 域外第三方盗用 grant | deny/grant-subject-mismatch | accept |
| 非授权签发者签 grant | deny/issuer-not-in-domain | accept |
| 无域凭证直连受治理技能 | deny/no-credential | accept |

**8/8 命中预期**。关键说服力：冻结/撤销/配额/到期四类变更，用的都是**同一枚已签发的 grant**，只是章程状态或计数器变了——直接证明协作域是运行时状态机，而非启动时的静态配置。

## ③ Workspace 四分区受控工作区

**对照方式**：普通业务写入（裸 `Path.write_text`，无分区/身份/台账约束） vs 受控工作区（`ws_create` + `ws_write`，四分区 + 令牌派生身份 + sha256 台账）。写入内容相同，唯一变量是走不走受控能力。

### 越界写入拒绝率

| 越界类型 | 普通写入 | 受控工作区 |
|---|---|---|
| repo 只读区写入 | 成功写入 | 拒绝（zone-readonly） |
| 非四分区路径 | 成功写入 | 拒绝（zone-required） |
| `..` 走廊越出 shared 分区 | 成功写入 | 拒绝（zone-escape） |
| products 覆盖写（if_match） | 成功写入 | 拒绝（products-append-only） |

**拒绝率：0%（普通）→ 100%（受控，4/4）**。

### 身份伪造拦截率（scratch 领地强制前缀）

冒写他人领地 `scratch/victim/secret.md`：
- 普通写入：原样落到 victim 目录，**伪造得逞**；
- 受控工作区：服务端强制归位到 `scratch/worker/victim/secret.md`，victim 领地零新增文件。

**拦截率 4/4 = 100%**——身份由令牌 `act.aic` 派生，写别人的领地在物理上不可能，只会被归位到调用方自己名下。

### 归因记录完整率

| 指标 | 结果 |
|---|---|
| 写记录四字段齐全（actor/path/bytes/sha256） | **8/8 = 100%** |
| `prev_sha256` 链（同一路径覆盖 3 次） | **2/2 环承接，完整** |
| 普通写入目录有台账 | 否（零归因） |

> 说明：`prev_sha256` 是"同一路径被覆盖前的旧哈希"（首写为空串）。对 `versioned.md` 连续覆盖 3 次，第 2、3 条的 `prev_sha256` 逐条等于上一条 `sha256`，链完整。报告里另有一个"sha256 与落盘文件一致 6/8=75%"的辅助数字——那是把历史记录去比当前文件，覆盖后对不上是预期行为，**不要把这个 75% 当成归因缺陷**，归因主口径是字段齐全率 100% 与链完整。

## ④ 双层 Guard

### 第一层·通信风险检测（对照=关闭检测，无告警）

复用官方红队 `guard-api/redteam/inject.py`，未改检测代码：

| 档 | 场景 | 得分 | 级别 | 命中规则 |
|---|---|---|---|---|
| A | 朴素外传·高熵 base64 | 30 | MEDIUM | encoded_high_entropy_blob |
| B | 时序调制·0/1 节拍 | 25 | LOW | alternating_interval_pattern |
| C | 规避版·切段+抖动+单调 | 0 | LOW | 无（漏报） |
| N | 正常轮询对照 | 20 | LOW | over_regular_intervals（误报） |

- 恶意检出 **2/2 = 100%**（A、B 均命中）
- 消融复活 **4/4**：C1 不切段=24、C2 不加抖动=20、C3 不分片=12、C4 状态往返=30——三条检测维度各自有效。

**诚实边界**（必须保留，别在答辩里藏）：
- **误报**：N 正常等间隔轮询触发 20 分 LOW（`over_regular_intervals`）。检测器为只读 advisory，不做自动拦截，误报不会阻断业务。
- **漏报**：C 规避版同时绕开载荷/时序/状态三维，检测 0 分。Guard 定位是"提高攻击成本 + 可解释告警"，不是 100% 检出。

### 第二层·运行守卫止损（对照=observe vs enforce）

场景：参数扫描卡死任务——每轮重复同一工具调用、无进度。repeat 阈值=16，步预算=195。

| | observe（只记录不阻断≈无止损） | enforce（真实中止） |
|---|---|---|
| 行为 | 跑满预算 195 次调用 | 第 16 次触发 repeat-loop 并中止 |
| 是否真正中止 | 否 | 是（`_RUN_GUARD_ABORT` 置位） |
| 消耗调用数 | 195 | 16 |

**止损收益：省下 179/195 次后续调用 = 91.8%**（单场景样例；更严谨的分布见下方 ④b）。

## ④b Guard 规模化评估（用分布替代单点，推荐对外口径）

上一节的 2/2 检出与 91.8% 止损都是**单案例**，样本太小（1 正常 + 3 攻击）。本节把样本扩到 **17 个正常任务 + 16 个异常任务**（固定种子 20261117，可复现），统计误报/漏报/止损的分布——比强调单一数字更有说服力，也更诚实。

### 正常样本 17 个 · 误报分布

| 指标 | 结果 |
|---|---|
| level 分布 | LOW 17 / MEDIUM 0 / HIGH 0 |
| score 分布 | min 0 / p50 0 / p95 22 / max 22 |
| 有误报（任意得分>0） | **6/17 = 35.3%** |
| 其中 MEDIUM+ 误报 | **0/17 = 0%** |

误报来源两类，各 3 例：**`over_regular_intervals`**（真实等间隔轮询）与 **`invalid_state_transition`**（`awaiting-input→working` 合法往返被判状态倒退）。

> **关键结论**：误报率 35% 看着高，但**全部停在 LOW，零 MEDIUM+ 误报**。检测器是只读 advisory（不自动拦截），LOW 级告警不会阻断业务——误报的代价只是"多看一眼日志"。

### 异常样本 16 个 · 检出/漏报分布

| 指标 | 结果 |
|---|---|
| level 分布 | HIGH 2 / MEDIUM 2 / LOW 12 |
| 检出（任意得分>0） | **13/16 = 81.2%** |
| 漏报（0 分） | **3/16 = 18.8%**（3 个规避版全部隐身） |
| MEDIUM+ 有意义告警 | 4/16 = 25% |

规则命中频次：高熵 blob 5、交替节拍 4、状态倒退 4、超大载荷 1、重复载荷 1、等间隔 1、高频切换 1。

> **诚实解读**：扩样后检出从"2/2=100%"降到 **81.2%**——这才是真实水平。所有漏报都来自规避版（同时绕开载荷/时序/状态三维）。Guard 的定位是**提高攻击成本 + 可解释告警**，不是 100% 检出；能否检出刻意规避的高级对手，本来就不是它的设计目标。

### 止损收益分布（9 场景：3 种卡死规则 × 3 个触发阈值）

| 触发阈值 | 节省调用 | 收益 |
|---|---|---|
| @8 | 187/195 | 95.9% |
| @16 | 179/195 | 91.8% |
| @32 | 163/195 | 83.6% |

**收益区间 83.6%–95.9%，中位 91.8%**（repeat-loop / error-streak / partner-not-finishing 三种规则同分布）。原来的 91.8% 只是 @16 这一档；分布口径说明止损在 8–32 轮触发区间内稳定省下八到九成后续调用。

## 不能说的 / 要如实标注的

1. 延迟是**本地纯裁决**耗时，不是端到端网络延迟；不要说"通信延迟仅 8ms"。
2. Guard 检出率用规模化口径 **81.2%（13/16）**，漏报 18.8% 来自规避版；**不要再说"100%检出"**（那只是早期 2/2 的小样本）。误报率 35.3% 但**全部 LOW、零 MEDIUM+**，上屏要一起说"误报停在 LOW、不阻断业务"，别只报 35%。
3. Guard 检测层是 advisory-only（只读旁路），**自动止损只在 enforce 模式的 RunGuardHooks 发生**，两层别混为一谈。
4. Workspace 的"sha256 与落盘文件一致 6/8=75%"是拿历史记录比当前文件的辅助数字，覆盖写后对不上是预期行为；归因主口径用"字段齐全 100% + prev 链完整"，不要引用 75%。
5. ①②④ 的签名链数字来自临时 CA 的自包含实验，与生产 dev CA 环境不同，但签名链/验签路径同构；口径上标"离线可复现对照实验"。③ Workspace 用模块级纯函数 + 临时目录，不涉证书。
6. 对照的"普通业务写入"是裸 `Path.write_text` 建模的无治理基线，不是某个具体竞品产品；上屏时说"无工作区治理的普通写入"，别说成"官方 SDK 写入"。
